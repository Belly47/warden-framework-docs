## `warden.UnitManager`

```lua
warden.UnitManager:Get(token)
warden.UnitManager:GetObject(guid)
warden.UnitManager:RegisterVirtualUnit(name, handler)
```

`Get` returns the framework unit wrapper for standard tokens such as `player`,
`target`, and `focus`. A virtual unit handler should return a valid unit wrapper
or the framework's `none` unit.

Dynamic native handles for party, raid, pet, arena, target, focus, and
mouseover units are invalidated by their roster/unit events. Keep the wrapper
and re-read its properties; do not cache a raw GUID or object pointer yourself.

## Player power and resources

Power values are numeric unit properties. They are normalized through Warden's
secret-value boundary, so use them directly in rotation comparisons instead of
calling `UnitPower` yourself:

```lua
-- Feral
if player.energy >= 50 and player.combopoints >= 5 then
  return spells.ferocious_bite:cast(target)
end

-- Guardian
if player.rage >= 40 and player.ragedeficit >= 20 then
  return spells.ironfur:cast(player)
end

-- Paladin
if player.holypower >= 3 then
  return spells.templars_verdict:cast(target)
end
```

Every supported resource has the same property family:

| Property | Meaning |
| --- | --- |
| `player.energy` | Current power. Replace `energy` with any supported resource. |
| `player.energymax` | Maximum power. |
| `player.energypct` | Current power as a percentage of maximum. |
| `player.energydeficit` | Amount missing before reaching maximum. |
| `player.energyregen` | Passive regeneration per second; `0` when unavailable. |
| `player.energytimetomax` | Seconds until full at the current passive regeneration rate; `math.huge` when it cannot regenerate. |

Supported names are `mana`, `rage`, `focus`, `energy`, `combopoints`,
`runes`, `runicpower`, `soulshards`, `astralpower`, `holypower`,
`alternatepower`, `maelstrom`, `chi`, `insanity`, `arcanecharges`,
`fury`, `pain`, and `essence`. Compatibility aliases are `cp` for
`combopoints`, `shards` for `soulshards`, and `ap` or `lunarpower`
for `astralpower`.

Runes use the same properties, with `player.runes` returning the number ready
and `player.runesmax` returning `6`. For an active threshold, use
`Unit:timeto(powerType, amount)`:

```lua
if player:timeto("energy", 50) <= warden.gcd() then
  return spells.tigers_fury:cast(player)
end

if player:runestimeto(2) <= 1.5 then
  return spells.death_and_decay:cast(player)
end
```

`Unit:timeto` returns `math.huge` when the requested resource does not have
positive passive regeneration. `Unit:runestimeto` is the rune-specific helper
for a requested ready-rune count.

## Enemy lists

```lua
warden.enemies          -- all valid nearby hostiles
warden.activeenemies    -- engaged hostiles only
warden.castingenemies   -- engaged enemies currently casting or channeling
warden.interruptibleenemies -- casting/channeling enemies that can be interrupted
target.enemiesaround(8) -- broad compatibility proximity count
player.enemiesincone(10, 90) -- hostiles in the player's 10 yd / 90 degree cone
```

An enemy is active only when Warden has engagement evidence: combat state, a
player/group target, positive threat, or DPS-dummy status. Unengaged nearby
packs remain in `enemies` and `enemiesaround` but not `activeenemies`.

Each hostile is represented once. When WGG supplies an opaque raw-object GUID
and a nameplate supplies the native GUID for that same NPC, Warden keeps the
native nameplate identity and suppresses the raw duplicate. This applies to
enemy callbacks, AOE/range counts, and caster lists. OM debug diagnostics show
the per-refresh `aliases` and `suppressed` counts when this recovery occurs.

## Active defensives

`unit.defensive` reports whether the unit has a recognized player-class
defensive aura. `unit.defensiveaura` returns that aura, and
`unit.defensivecategory` returns one of `reduction`, `absorb`, `immunity`, or
`majorHealing`. `unit.defensivecoverage` returns `all`, `physical`, `magic`,
or `none`.

```lua
if player.defensive then
  -- Avoid overlapping another personal defensive.
end

warden.interruptibleenemies:each(function(enemy)
  -- Generic PvE kick candidate.
end)

local priority = warden.UnitManager.prio_int_target
```

The defensive catalogue covers player-class personal and external defensives.
Dungeon and raid NPC shields remain encounter-specific rotation data.

Warden treats these current training-dummy NPCs as hostile and active for safe
rotation testing without needing combat: `243166` (Normal Tank Dummy),
`243167`/`243168` (Dungeoneer's Training Dummy), `243207`/`243214` (Training
Dummy), `243208` (Cleave Training Dummy), and `243211` (PvP Training Dummy).
They are still distance-filtered by range APIs such as `enemiesaround(40)`.

For `player.enemiesaround(range)`, Warden combines WGG's native hostile-range
count with the managed hostile list and a confirmed current target fallback. The
largest confirmed count wins, so a transient native zero or object-list rebuild
cannot erase a target already known to be hostile and in range. The native count
is range-based and does not require line of sight or camera visibility.

Packages that genuinely need an out-of-combat object snapshot can register a
scan demand and release it when their widget or feature is hidden:

```lua
warden:SetObjectManagerScanDemand("my-package-widget", true)
warden:SetObjectManagerScanDemand("my-package-widget", false)
```

Keep the demand scoped to actual use; scanning is otherwise suspended outside
combat when no enabled rotation or visible Insight consumer needs it.

## Frontal-cone queries

Use a cone query for abilities whose hit area is in front of the player, such
as Shockwave. The arc is the total width in degrees, not a half-angle:

```lua
if player.enemiesincone(10, 90) >= 3 then
  return spells.Shockwave:cast(player)
end

local targets = warden.GetEnemiesInCone(player, 10, 90)
local engaged = warden.CountEnemiesInCone(player, 10, 90, { activeOnly = true })
```

`Unit:enemiesincone(range, arc, activeOnly?)` is the public method; dot syntax
(`player.enemiesincone(...)`) and `player.enemiesinfrontalcone(...)` are
compatible aliases. `GetEnemiesInFrontalCone` and `CountEnemiesInFrontalCone`
are aliases for the framework functions. Queries fail closed when a position
or facing value is unavailable, so an uncertain object-manager snapshot never
inflates an AOE count.

## Enemy clusters

Clusters use the full nearby-hostile snapshot by default, including unengaged
packs. That makes them suitable for preparation before initiating combat:

```lua
local cluster = warden.EnemyCluster(target, 8)
if cluster.count >= 2 and spells.SweepingStrikes:ready() then
  return spells.SweepingStrikes:cast(player)
end

local densest = warden.LargestEnemyCluster(8)
```

Pass `{ activeOnly = true }` to use only engaged enemies. A cluster exposes
`anchor`, `members` (`warden.List`), `radius`, and `count`.

## Stances and forms

Player aura queries include active Druid forms, Paladin auras, and Warrior
stances. Warden resolves the active form index with `GetShapeshiftForm()` and
uses `GetShapeshiftFormInfo()` for the corresponding spell ID, so a manually
selected Warrior stance is reflected by `player:aura(...)` and
`player:aurafrom(...)` immediately after its form event. The direct helper is
`warden.IsStanceActive(spell)`.

## `warden.List`

```lua
local list = warden.List:New(values)
list:each(callback)
list:first(predicate)
list:filter(predicate)
list:count()
```

Other stable list operations are `push`, `pop`, `peek`, `contains`, `remove`, `map`, `find`, `findIndex`, `sort`, `reverse`, `clone`, `concat`, and `join`.

## `warden.Aura`

```lua
local aura = warden.Aura:New(auraData)
local seconds = aura:remains()
```

Aura data can disappear between ticks. Check that the aura exists before reading it.

## Unit aura calls and forms

These calls support both legacy dot syntax and ordinary colon syntax:

The public signatures are `Unit:aura(spell, source?)`,
`Unit:auraremains(spell, source?)`, `Unit:auracount(spell, source?)`, and
`Unit:aurauptime(spell, source?)`.

```lua
local auraA = player.aura(spells.BattleStance.id)
local auraB = player:aura(spells.BattleStance.id)

local remains = player:auraremains(spells.BattleStance.id)
local stacks = player:auracount(spells.BattleStance.id)
local uptime = player:aurauptime(spells.BattleStance.id)
```

For the player, active Druid forms, Warrior stances, and supported Paladin
form/aura-bar states are represented as synthetic auras when the client does
not publish a normal unit aura. Synthetic form auras have a stable spell ID,
source, count, start time, uptime, and indefinite (`999`) remains value.

Prefer the direct stance helper when the intent is a state check:

```lua
if not warden.IsStanceActive(spells.BattleStance) then
  return spells.BattleStance:cast(player)
end
```

## PvP unit state

Unit wrappers expose `cc`, `immune`, `immunemagic`, and `immunephysical`.
Compatibility aliases include `iscc`, `CC`, `ccimmune`, `isimmune`, `Immune`,
and `immunities`. These names report the maintained CC-immunity contract, not
a general guarantee that every damage or soft-control effect is blocked.

The corresponding property names are `Unit.cc`, `Unit.immune`,
`Unit.immunemagic`, and `Unit.immunephysical`.

`Unit:v2Attackers(option?, ignoreRange?)` and lowercase
`Unit:v2attackers(...)` count hostile DPS pressure on the receiver. See
[PvP rotation basics](/pvp#count-attackers-on-an-ally) for options and return
ordering.
