---
title: "Spell Queue"
description: "Configure action-bar keybind targets without changing your rotation routine."
---

Spell Queue stores an enabled state and target mode for each action-bar slot, per character, class, and specialization. Enable a slot in the Smart Queue layout, then click its mode column to cycle through the available targets.

The saved key contains the character name, class, specialization, and action
slot. Changing specialization therefore restores that specialization's own
mode choices without overwriting another setup.

## Target modes

| Mode | Target |
| --- | --- |
| `Target` | Your current target. |
| `Player` | Your character. |
| `Mouseover` | Your live mouseover unit. |
| `Healer` | The nearest valid friendly healer. |
| `Enemy Healer` | The nearest valid hostile healer. |
| `Lowest Ally` | The lowest-health valid ally, excluding healing-immune allies. |
| `Lowest Enemy` | The lowest-health valid hostile enemy. |
| `Friends` / `Enemies` | The best eight-yard friendly or hostile cluster for area effects. |
| `Cursor` | Blizzard's normal ground-placement cursor. |

## How queued actions work

Target modes directly select a unit for spell actions. Macros and other action-bar items still run from their original slot, so the macro's own target conditions remain in control.

`Lowest Ally` includes the player and friendly group units, ignores dead units and configured healing-immunity targets, then uses nearest distance to break equal-health ties. `Lowest Enemy` uses active hostile units and falls back to your current hostile target if the object-manager list is temporarily sparse.

Units with unresolved health are not allowed to win a lowest-health choice.
Healer selection is deterministic: Warden merges native group/arena tokens
with object-manager units, deduplicates them by canonical GUID, and chooses the
nearest eligible healer with a stable GUID tie-break.

Friendly and enemy cluster choices are cached for the queued entry and current
object-manager generation, so the eight-yard calculation is not repeated on
every queue pulse.

If the selected unit disappears or fails the spell's normal range or line-of-sight checks, the queued cast does not choose a different target afterward. Pick the mode that matches the spell's intended target.

For example, bind a direct heal to `Lowest Ally`, a purge or execute to
`Lowest Enemy`, a peel to `Enemy Healer`, and a self-defensive to `Player`.
Macros keep their own action-bar targeting clauses, so a macro using
`[@mouseover]` or modifier conditions remains responsible for those choices.

## Adaptive `SpellQueueWindow`

**Settings > Modules > Queue** includes an optional optimizer for Blizzard's
`SpellQueueWindow` CVar. It targets observed world latency plus a configurable
safety margin (100 ms by default), then clamps the result to 100-400 ms. A
40 ms hysteresis avoids rewriting the CVar for insignificant latency noise.

The optimizer is off by default and never writes the CVar in combat. A deferred
sample is retried immediately when combat ends. Disabling the option only stops
future changes; it deliberately leaves your current CVar value in place. The
framework's Spell Handler already reads the live queue window, so this tunes
the existing queue behaviour rather than creating a second queue.
